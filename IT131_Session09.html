Module 12 · 12.1

Why IPv6 exists

IPv4 has about 4.3 billion addresses, and the free pool ran out years ago. Internet growth, the problems NAT causes, and billions of IoT devices all need more. IPv6 has 128-bit addresses: about 340 undecillion (3.4 × 10³⁸).

Three ways IPv4 and IPv6 coexist

The internet can't switch over in one night, so ITN names three migration techniques. The goal is native IPv6 everywhere. The other two are only for where it's needed.

TechniqueHow it worksThink of it as
Dual stackDevices run IPv4 and IPv6 at the same time, each with its own address.Speaking two languages
TunnelingAn IPv6 packet is carried inside an IPv4 packet across an IPv4-only network.A letter mailed inside another envelope
Translation (NAT64)A device translates between IPv6 and IPv4, so an IPv6-only host can reach an IPv4-only one.An interpreter

Module 12 · 12.2

Writing an IPv6 address

128 bits written as eight hextets (16 bits, 4 hex digits each) separated by colons. Hex isn't case-sensitive. Two rules shorten the address.

RuleWhat it doesWatch out
1 · Omit leading zerosDrop zeros at the front of any hextet: 0db8 → db8, 0000 → 0.Never trailing zeros. 0200 becomes 200, not 2.
2 · Double colonReplace one run of consecutive all-zero hextets with ::.Only once per address. Two would make it impossible to tell how many zeros each one hides.
ITN's own example 2001:0db8:0000:1111:0000:0000:0000:0200 → rule 1 → 2001:db8:0:1111:0:0:0:200 → rule 2 → 2001:db8:0:1111::200. The single 0 in the 3rd hextet can't join the ::, because it isn't next to the longer run.

Module 12 · 12.3

IPv6 address types

Three categories: unicast (one device), multicast (a group), and anycast (one address on several devices, delivered to the nearest). There is no broadcast in IPv6. The all-nodes multicast group, ff02::1, does that job.

TypeRangeWhat it's for
Global unicast (GUA)2000::/3Globally unique and routable on the internet, like a public IPv4 address. Today's GUAs start with a 2 or 3.
Link-local (LLA)fe80::/10Only valid on one link, and never routed. Every IPv6 interface must have one, and a device creates it automatically. Routers use LLAs to talk to their neighbors, and a host's default gateway is normally the router's LLA.
Unique local (ULA)fc00::/7For internal use, somewhat like RFC 1918, but not meant to be hidden behind NAT. Rarely used.
Multicastff00::/8A group of devices. Only ever a destination, never a source.
Loopback::1The device itself, like 127.0.0.1. ping ::1 tests the local IPv6 stack (Module 13).

Structure of a GUA

2001:db8:acad:1::10/64, split into its three parts
2001:0db8:acad:0001:0000:0000:0000:0010 └─── 48 bits ──┘ └16┘ └────── 64 bits ──────┘ Global routing Subnet Interface ID prefix (ISP) ID (the host part)

The ISP assigns the global routing prefix, usually a /48. The 16-bit subnet ID is yours to number, which gives 65,536 subnets. The 64-bit interface ID identifies the device. A /64 is recommended for every LAN, because SLAAC (below) needs a 64-bit interface ID.

The #1 reason "IPv6 doesn't work" in Packet Tracer ip routing is on by default. ipv6 unicast-routing is off by default. Without it, R1's interfaces still take their addresses, but R1 acts like an IPv6 host: it won't forward IPv6, and it won't send Router Advertisements. PCs on LAN-A using SLAAC then get no global address and no default gateway, only their own fe80:: address.
Same fe80::1 on two interfaces? That's legal. A link-local address only has to be unique on its own link, and each interface is a different link. ITN says using a different LLA on each interface is common practice, and either choice works. Giving the router an easy LLA like fe80::1 makes it a memorable default gateway.

  • L FF00::/8 via Null0 is added automatically for the multicast range. Nobody configured it.
  • Reaching LAN-B would need a static IPv6 route, which is CCNA 2 material, the same as the IPv4 static routes in Session 7.

Module 12 · 12.5 – 12.6

Dynamic addressing: SLAAC and DHCPv6

Hosts usually don't get IPv6 addresses typed in by hand. They ask the router, using two ICMPv6 messages.

MessageDirectionWhat it does
Router Solicitation (RS)Host → all routers (ff02::2)"Is there a router here? Tell me how to get an address." A booting host sends one right away, so it doesn't have to wait.
Router Advertisement (RA)Router → all nodes (ff02::1)Carries the prefix, the prefix length, and which method to use. The router's LLA, the RA's source address, becomes the host's default gateway. Routers send RAs every 200 seconds, and immediately in reply to an RS.

The three methods

MethodHost's GUA comes fromDNS and other infoDefault gateway
1 · SLAAC onlyThe RA's prefix plus an interface ID the host makes itselfThe RARouter's LLA, from the RA
2 · SLAAC + stateless DHCPv6SLAAC, as aboveA stateless DHCPv6 serverRouter's LLA, from the RA
3 · Stateful DHCPv6A stateful DHCPv6 server, which keeps track of who has which addressThe DHCPv6 serverRouter's LLA, still from the RA
The testable nuance Even with stateful DHCPv6, the default gateway always comes from the router's RA. DHCPv6 never provides a gateway. That's a real difference from DHCPv4.
Preview, not on this checkpoint: the RA flags (CCNA 2) The RA signals which method to use with three flags: A (use SLAAC), O (get Other info from stateless DHCPv6), and M (Managed, meaning stateful DHCPv6). The commands that set them, such as ipv6 nd other-config-flag and ipv6 nd managed-config-flag, are CCNA 2 (SRWE Module 8) material. ITN only asks you to know the three methods by name and what each provides.

What a SLAAC host shows

PC-A (Windows 10/11, dual stack): ipconfig
C:\> ipconfig Ethernet adapter Ethernet: Connection-specific DNS Suffix . : IPv6 Address. . . . . . . . . . . : 2001:db8:acad:1:3c1a:9b2f:6d4e:8a71 Temporary IPv6 Address. . . . . . : 2001:db8:acad:1:c49d:12e5:77a0:b3f2 Link-local IPv6 Address . . . . . : fe80::a5d0:61c4:2e9b:17f3%12 IPv4 Address. . . . . . . . . . . : 192.168.10.10 Subnet Mask . . . . . . . . . . . : 255.255.255.0 Default Gateway . . . . . . . . . : fe80::1%12 192.168.10.1
  • The prefix 2001:db8:acad:1 came from R1's RA. The rest is the interface ID the PC made itself.
  • %12 is a zone ID, the PC's own number for that network interface. It isn't part of the address, and the number varies from PC to PC. It's needed because every link uses fe80::, so the PC has to say which interface it means.
  • Temporary IPv6 Address is a privacy address. It changes periodically and is used for outgoing connections.
  • Default Gateway shows R1's link-local address. That's normal and correct.

The interface ID values above are just examples. Windows generates random interface IDs, which it has done since Vista. Packet Tracer PCs show a simpler format, using EUI-64 interface IDs built from the PC's MAC address.

Duplicate Address Detection (DAD)

Before using a new address, a host checks that nobody else already has it. It sends a Neighbor Solicitation asking for its own address. If a Neighbor Advertisement comes back, someone already owns it. It works like ARPing for your own IP.

Link-local addresses are automatic

Every IPv6 interface creates its own LLA: fe80:: plus an interface ID, either EUI-64 or random. Windows uses the same method it uses for its SLAAC address. A Cisco router creates an EUI-64 LLA automatically the moment an interface gets a GUA, unless you set one with the link-local keyword, as above.

Module 12 · 12.5 – 12.6

EUI-64: an interface ID from a MAC address

A MAC address is 48 bits, and an interface ID needs 64. EUI-64 stretches the MAC and flips one bit.

StepDo thisMAC fc:99:47:75:ce:e0
1Split the MAC in halffc:99:47 | 75:ce:e0
2Insert ff:fe in the middle, making 64 bitsfc:99:47:ff:fe:75:ce:e0
3Flip the 7th bit of the first bytefc = 1111 1100 → 1111 1110 = fe
4Group into hextets: that's the interface IDfe99:47ff:fe75:cee0
5Add a prefixfe80::fe99:47ff:fe75:cee0
2001:db8:acad:1:fe99:47ff:fe75:cee0
Shortcut for the flip Flipping the 7th bit means adding or subtracting 2 in the first hex byte. In practice, change only the second hex digit: 0→2, 2→0, 4→6, c→e, e→c, and so on. So fc→fe, 00→02, and 70→72. ITN's router example checks out: MAC 7079.b392.3640 gives FE80::7279:B3FF:FE92:3640.
Heads up: one ITN slide gets this wrong ITN's Windows EUI-64 ipconfig example shows fe80::fc99:47ff:fe75:cee0, which skips the flip. Its own EUI-64 process slide, using the same MAC, correctly gives fe99…. Trust the process. The correct answer is fe99:47ff:fe75:cee0. Also, the bit is flipped, not "set to 1": a MAC that already has it set goes from 1 to 0.

Spotting EUI-64: an EUI-64 interface ID always has ff:fe in the middle, so you can read the MAC back out of the address. That's the privacy problem: the device can be tracked across networks. It's why Windows uses random interface IDs instead.

Try it: MAC → EUI-64 → addresses

Module 12 · 12.7

IPv6 multicast

All multicast addresses sit in ff00::/8. ITN covers two kinds: well-known groups, and solicited-node groups.

AddressGroupWho's in it
ff02::1All-nodesEvery IPv6 device on the link. It takes the place of broadcast, and periodic RAs are sent here.
ff02::2All-routersEvery IPv6 router on the link. A router joins once ipv6 unicast-routing is on, and RSs are sent here.

Solicited-node multicast

IPv6 has no ARP broadcast. To find a neighbor's MAC address, a device sends a Neighbor Solicitation to a small multicast group that, in practice, only the target is in. The group is built from the target address: ff02::1:ff followed by the last 24 bits (last 6 hex digits) of that address.

Target addressLast 24 bitsSolicited-node group
2001:db8:acad:1::1000:0010ff02::1:ff00:10
2001:db8:acad:1:fe99:47ff:fe75:cee075:cee0ff02::1:ff75:cee0
fe80::fe99:47ff:fe75:cee075:cee0ff02::1:ff75:cee0 (same group)
2001:db8:acad:1::1 and fe80::100:0001ff02::1:ff00:1
Why bother The NIC can tell from the destination MAC whether a frame is for a group it joined, and it drops everything else in hardware. So a solicited-node message acts like "a broadcast only the probable owner hears." Session 6 compared NDP with ARP. This is the mechanism behind that comparison. DAD uses the same trick, just targeting the host's own address.

Module 12 · 12.8

Subnetting an IPv6 network

IPv6 was designed for subnetting. There's a dedicated subnet ID field, so you never borrow host bits.

Given 2001:db8:acad::/48, the 16-bit subnet ID gives 65,536 /64 subnets. You count up the fourth hextet in hex (:0::, :1::, … :9::, :a::, … :ffff::), and the prefix and interface ID stay untouched. Every LAN and every point-to-point link gets its own /64. The waste doesn't matter: there are 65,536 subnets to spend, a /64 on every link keeps the plan simple, and on LANs it keeps SLAAC working.

Full treatment and practice The Subnetting Field Manual's IPv6 section has the hex-counting table, how to read a subnet out of an address, and an IPv6 subnet-ID drill. Watch the classic trap: subnet ten is :a:, and :10: is sixteen.

Module 13 · 13.1

ICMP messages

IP delivers packets but never says what went wrong. ICMP is how devices report problems and test reachability. ICMPv4 serves IPv4. ICMPv6 serves IPv6 and does much more.

In the OSI Company

ICMP is Logistics' incident desk. When a shipment can't be delivered, it sends back a report saying why: no route to that part of town, the address doesn't exist, or the package ran out of hops. It rides directly inside IP, with no TCP or UDP and no port numbers.

Messages in both ICMPv4 and ICMPv6

MessageWhat it means
Echo Request / Echo Reply"Are you there?" / "Yes." This is ping.
Destination UnreachableA router or host couldn't deliver the packet. A code says why (below).
Time ExceededThe packet's TTL (IPv4) or Hop Limit (IPv6) reached 0, so a router dropped it. This is what traceroute relies on.
CodeICMPv4 Destination UnreachableICMPv6 Destination Unreachable
0Net unreachableNo route to destination
1Host unreachableCommunication administratively prohibited (e.g., a firewall)
2Protocol unreachableBeyond scope of the source address
3Port unreachableAddress unreachable
4(not covered in ITN)Port unreachable

ICMPv6-only: Neighbor Discovery

MessageBetweenUsed for
Router Solicitation (RS)Host → routersAsking for an RA
Router Advertisement (RA)Router → hostsPrefix, method, and default gateway (SLAAC)
Neighbor Solicitation (NS)Device → deviceAddress resolution (the IPv6 version of an ARP request), and DAD
Neighbor Advertisement (NA)Device → deviceThe reply to an NS, carrying the MAC address
Don't block all ICMP ICMPv4 is often filtered for security, and that's workable. In IPv6, RS, RA, NS, and NA are ICMPv6. Block ICMPv6 entirely and hosts can't get addresses or find their neighbors.

Module 13 · 13.2

Ping and traceroute

Ping asks "can I reach it?" Traceroute asks "which way does it go, and where does it stop?"

The ping ladder: test from the inside out

StepCommandIf it worksIf it fails
1ping 127.0.0.1
ping ::1		The host's IPv4/IPv6 stack is installed and working.TCP/IP isn't working on the host. This tests nothing on the NIC, cable, or network, because the packet never leaves the host.
2ping 192.168.10.1
(default gateway)		The host, its local network, and the router's interface all work.The problem is between the host and the router. Ping another host on the same LAN to narrow it down.
3ping 192.168.20.10
(remote host)		Routing works in both directions.A routing problem, or the remote side is filtering ICMP. Run traceroute to find where it stops.

On a Cisco router it's common for the first ping to time out while ARP (or ND) resolves the address (you'll see .!!!! below). Windows usually doesn't lose it. One lost reply at the start isn't a fault.

TTL=255 isn't a hop count The TTL= in a reply is the TTL left in the reply packet. Cisco routers start replies at 255, Windows at 128, and Linux at 64. You can sometimes guess what answered from it, but it doesn't tell you how many hops away the target is.

How traceroute works

  1. 1. Send probes with TTL (or Hop Limit) = 1. The first router drops them and sends back Time Exceeded. That router is hop 1.
  2. 2. Send with TTL = 2. They expire one router further on. That's hop 2.
  3. 3. Keep going until the destination itself replies, or the limit (30 by default) is hit. Three probes are sent per hop, which gives the three time columns.
PC-A traces to PC-B
C:\> tracert 192.168.20.10 Tracing route to 192.168.20.10 over a maximum of 30 hops 1 <1 ms <1 ms <1 ms 192.168.10.1 2 1 ms 1 ms 1 ms 10.0.0.2 3 2 ms 1 ms 1 ms 192.168.20.10 Trace complete.
A hop that doesn't answer, but still forwards
1 <1 ms <1 ms <1 ms 192.168.10.1 2 * * * Request timed out. 3 2 ms 1 ms 1 ms 192.168.20.10 Trace complete.
  • Each hop shows the interface that sent the Time Exceeded, usually the one facing you. Hop 2 is R2's 10.0.0.2, not its LAN address.
  • A * hop followed by answering hops means that router forwards fine but is configured not to reply. That's common on the real internet.
  • A broken path answers for a few hops, then shows * * * Request timed out. all the way to hop 30. The problem is just after the last hop that answered. Press Ctrl-C to stop it.
  • The last hop replies differently. Windows tracert sends ICMP echoes, so the destination sends an Echo Reply. Cisco IOS traceroute sends UDP to an unused port, so the destination replies Port Unreachable. (Module 17 detail.)

Watch for this

Common Module 12–13 mistakes

These come up every semester.

  • Saying IPv6 has a broadcast address. It doesn't. ff02::1 does that job.
  • Using :: twice, or dropping trailing zeros (0200 → 2 is wrong; it's 200).
  • Forgetting ipv6 unicast-routing. Hosts then get no global address and no gateway.
  • Leaving off /64, or leaving off the link-local keyword, in the ipv6 address command.
  • Thinking the gateway must be the router's global address. The router's LLA is normal and is best practice.
  • Treating the %12 zone ID as part of the address.
  • Thinking DHCPv6 provides the default gateway. The gateway always comes from the RA.
  • EUI-64: forgetting the 7th-bit flip, flipping the wrong bit (fc→fd), or putting fffe in the wrong place.
  • Solicited-node: using the last 32 bits instead of 24, or building it from the sender's address instead of the target's.
  • Thinking a loopback ping tests the NIC or cable. It only tests the local stack.
  • Reading "Destination host unreachable … 0% loss" as a success.
  • Thinking a failed ping means the host is down. It could be a firewall, or a missing return route.
  • Reading a * hop in tracert as "that router is down" when later hops still answer.

Compression

Shorten it as far as the rules allow

2001:0db8:0000:0000:00a0:0000:0000:0001

Show answer

Rule 1 gives 2001:db8:0:0:a0:0:0:1. There are two runs of two zero hextets, and :: can replace only one of them. By convention, use it on the first (leftmost) run of equal length: 2001:db8::a0:0:0:1. Note that a0 keeps its trailing zero.

EUI-64

Build the link-local address

A router interface has MAC 00:1b:2c:3d:4e:5f and no static LLA. What link-local address does IOS create?

Show answer

Split: 00:1b:2c | 3d:4e:5f. Insert ff:fe: 00:1b:2c:ff:fe:3d:4e:5f. Flip the 7th bit: 00 → 02. The interface ID is 021b:2cff:fe3d:4e5f, so the LLA is fe80::21b:2cff:fe3d:4e5f. The leading zero of 021b drops under rule 1.

SLAAC

No global address on the PCs

R1's G0/0/1 has 2001:db8:acad:1::1/64 and is up/up. PCs on that LAN are set to get IPv6 automatically, but ipconfig shows only an fe80:: address and no IPv6 default gateway. What's missing?

Show answer

ipv6 unicast-routing in global config. Without it, R1 doesn't send Router Advertisements, so the PCs never learn the prefix or the gateway. They only have the link-local address they create for themselves.

Ping

Which failure is which?

PC-A (192.168.10.10) has its default gateway set to 192.168.10.254, but the router is actually .1. PC-A pings 192.168.20.10. What output do you expect, and why?

Show answer

Reply from 192.168.10.10: Destination host unreachable., repeated. The target is off-subnet, so PC-A ARPs for its gateway, .254. Nothing answers, so the PC never sends the ping and reports the failure itself, from its own address. The summary will even say 0% loss.

Traceroute

Where did it stop?

tracert 192.168.20.10 from PC-A shows hop 1 192.168.10.1, then * * * Request timed out. on every hop up to 30. PC-A can ping its gateway. Where should you look?

Show answer

Look at R2 first, especially its route back to 192.168.10.0/24. R1 answered hop 1, so the LAN and R1 are fine. R1 also has a working route onward: with no route, or with the R1–R2 link down (its static route via 10.0.0.2 would drop out of the table), R1 would answer with Destination net unreachable from 192.168.10.1 instead of staying silent. Silence at hop 2 usually means R2 receives the probes but can't send its Time Exceeded replies home. That's Session 7's one-sided static route. A router set not to answer would be the other explanation, but then later hops would still answer.

Solicited-node

Which group does the NS go to?

R2 needs PC-B's MAC. PC-B's address is 2001:db8:acad:2::a:b5. What's the destination of R2's Neighbor Solicitation?

Show answer

Expand the last two hextets: 000a:00b5. The last 24 bits are 0a:00b5. The group is ff02::1:ff0a:b5. It's built from the target (PC-B), not from R2.
