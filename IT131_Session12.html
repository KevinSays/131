Quiz + practice lab

What Session 12 covers

No new modules this week. We start with the module quiz on Modules 16–17, then spend the rest of class on a practice lab that pulls the whole course together: cabling, subnetting, basic device configuration, IPv4 and IPv6 addressing, device hardening, SSH, and verification.

Cold open · HQ, Friday, 4:55 p.m.

The last network tech left a sticky note on an unopened box: "Shipping & Receiving side is done. R2, S2, PC-B, and the web server are up. HQ is all yours. Good luck." Inside: a router, a switch, a PC, and a tangle of cables. The Front Desk opens Monday at 8. By then, PC-A has to load www.it131.example, and nobody without a password gets into anything.

  • Choose and connect the right cables: straight-through, crossover, console
  • Subnet an address block with VLSM and plan an IPv6 /64
  • Do a full basic configuration on a router and a switch
  • Address router interfaces with IPv4, IPv6 GUA, and link-local, and give a switch a management address
  • Harden both devices and set up SSH-only remote access
  • Configure a host with IPv4, IPv6, and DNS
  • Verify the build end to end, and save it

Module Quiz — Building and Securing a Small Network

Quiz day: Modules 16–17

The quiz comes first. Everything on it is on the Session 11 page.

  • The Session 11 checkpoint lists everything the quiz covers.
  • Redo the Session 11 sample questions cold.
  • Run a full round of name that attack.
  • Be able to type the hardening and SSH commands from memory. You'll need them in the lab anyway.
The most-missed points A worm spreads itself; a virus needs a user. Ping sweeps and port scans are reconnaissance. Authentication is who you are, authorization is what you may do. In IOS ping, . is a timeout and U is unreachable. And 169.254.x.x means DHCP failed.

Practice lab

The lab: finish the HQ network

This lab works like Cisco NetAcad's Packet Tracer Skills Assessment (PTSA): you get a topology, an addressing table, and a list of requirements, and you configure the devices yourself. Every task is something a grader can check.

  • What you configure: R1, S1, and PC-A, including cabling them.
  • What's already done: R2, S2, PC-B, and SRV1 (the web server and DNS server for it131.example). Don't change them.
  • What you need: Cisco Packet Tracer, and the starting file from your instructor.
  • How long: plan on about 75 minutes the first time. The real skills exam is timed.
One provided step: static routes (CCNA 2 preview) R1 needs a route to LAN-B. Reading routing tables is Module 8, but configuring routes to remote networks is CCNA 2 (SRWE 15). Step 4.5 gives you the two route commands to type exactly. You're not expected to design them; just know that an S in the routing table means a static route. The real NetAcad skills exam avoids this by using one router; this lab uses two so that you can test DNS, the web, and SSH against a real server.
For instructors: building the starting .pkt

Build the whole topology, configure the right side as below, and leave R1, S1, and PC-A as factory-default devices (or leave them out and have students add them, per step 1.1). Cabling on LAN-B: S2 F0/1 → PC-B, S2 F0/2 → SRV1, S2 G0/1 → R2 G0/1. On SRV1, turn on HTTP and DNS, with an A record www.it131.example → 192.168.20.100. Consider an enable secret on R2 that students don't know, so nobody "fixes" the far side. If you build the finished network in Packet Tracer's Activity Wizard from the answer key, you get automatic scoring.

Block sizes 64, 32, 16, 4. The next free address is 192.168.30.116, leaving .116–.255 for growth. The router takes the first usable address in each subnet, as everywhere else on this site. For IPv6, the site uses 2001:db8:acad::/48 and subnet IDs 1, 2, and ff01 are taken, so LAN-C gets the next one: 2001:db8:acad:3::/64, with the router at 2001:db8:acad:3::1/64.

The three fill-ins in the build: R1 G0/0's mask is 255.255.255.252 (a /30). A /30 has 2 usable hosts. PC-A's IPv6 default gateway is R1's link-local address, FE80::1.

From PC-A

PC-A · ping by name
C:\> ping www.it131.example Pinging 192.168.20.100 with 32 bytes of data: Request timed out. Reply from 192.168.20.100: bytes=32 time<1ms TTL=126 Reply from 192.168.20.100: bytes=32 time<1ms TTL=126 Reply from 192.168.20.100: bytes=32 time<1ms TTL=126 Ping statistics for 192.168.20.100: Packets: Sent = 4, Received = 3, Lost = 1 (25% loss),

The first request often times out while ARP resolves along the path; ping again and you should get 4 of 4. TTL=126 means SRV1 (which starts at 128) is two routers away. Real Windows also prints the name: Pinging www.it131.example [192.168.20.100].

PC-A · tracert
C:\> tracert www.it131.example Tracing route to 192.168.20.100 over a maximum of 30 hops: 1 0 ms 0 ms 0 ms 192.168.10.1 2 0 ms 0 ms 0 ms 10.0.0.2 3 0 ms 0 ms 0 ms 192.168.20.100 Trace complete.

Hop 2 is R2's interface facing R1 (10.0.0.2), not its LAN-B address. Routers answer from the interface the probe arrived on.

PC-A · nslookup
C:\> nslookup www.it131.example Server: [192.168.20.100] Address: 192.168.20.100 Non-authoritative answer: Name: www.it131.example Address: 192.168.20.100
A Packet Tracer quirk Packet Tracer prints "Non-authoritative answer" even though SRV1 owns the it131.example zone. On real gear, an answer from the zone's own server has no such line (see Session 10). Ignore it here; the Name and Address lines are what count.
PC-A · SSH to R1
C:\> ssh -l admin 192.168.10.1 Password: Authorized access only. All activity is monitored. R1> enable Password: R1# exit [Connection to 192.168.10.1 closed by foreign host]
  • Passwords don't echo as you type.
  • You land at R1>, user EXEC, because the local user has no privilege level set. enable asks for the enable secret (En@ble2026), not the admin password.
  • On real IOS, the MOTD banner appears after you log in over SSH. Packet Tracer may show it in a slightly different spot.
  • This is Packet Tracer's SSH client. Connecting from a real PC to real gear can need extra options; see Session 2.

Watch for this

Common lab point-losers

The ways people lose points on the skills exam, every semester.

  • Forgetting no shutdown on router interfaces. Router ports start administratively down. Switch ports don't, but the switch's VLAN 1 interface does.
  • A straight-through cable between R1 and R2, or a console cable where an Ethernet cable belongs.
  • A wrong or missing gateway on PC-A, or the wrong mask. (Session 11's .254 scenario is exactly this.)
  • Adding IPv6 addresses without ipv6 unicast-routing. The interfaces get addresses, but R1 won't route IPv6.
  • Setting PC-A's IPv6 gateway to R1's global address instead of FE80::1, or leaving it blank. NetAcad and the skills exam use the link-local address.
  • SSH keys that won't generate: the hostname is still Router/Switch, or the domain name is missing. A typo like it131.exmaple still generates keys, but loses the step.
  • Typing security passwords min-length 8 after the passwords. It doesn't re-check existing passwords.
  • Using login instead of login local on the vty lines, or forgetting transport input ssh, which leaves Telnet open.
  • An incomplete S1 management setup: no no shutdown on VLAN 1, or no ip default-gateway. Without no shutdown, S1 has no reachable address at all. Without ip default-gateway, it answers on its own LAN but not from other subnets.
  • A banner that isn't exact, or a delimiter character inside the message. A # in the text ends the banner early.
  • No DNS server on PC-A: ping by IP works, ping by name fails. nslookup tells them apart.
  • Not saving. If it isn't in startup-config, a reload wipes it.
