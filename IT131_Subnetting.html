What subnetting is, and the order to learn it

Subnetting means splitting one block of IP addresses into smaller blocks, one per network segment. Each block needs a boundary that every router and host can calculate the same way.

Note

Subnetting is the one CCNA1 skill that is pure arithmetic. You don't memorize output or recall a protocol from a list. Nearly everyone finds it confusing the first time, and nearly everyone gets fast at it with practice. Learn the method, then do a lot of problems.

Why networks get subnetted

  • Smaller broadcast domains. Every ARP request and DHCP Discover goes to every host on the segment. Putting 50 hosts on each segment instead of 5,000 keeps that noise down.
  • Security boundaries. Traffic between subnets has to pass through a router, where it can be filtered. Guests, servers, and HR can each get their own subnet.
  • Organization. When each floor, building, or department gets its own block, an address alone tells you where a device is.
  • Less waste. Sizing each subnet to what it actually needs (VLSM) conserves a limited IPv4 supply.

Concepts

Anatomy of an IPv4 address

Every IPv4 address has two parts: a network portion, which is the same for every device on the subnet, and a host portion, which is unique to each device. The subnet mask marks where one part ends and the other begins.

Mask and prefix length: two ways to write the same boundary

  • Subnet mask — 32 bits, a 1 for every network bit and a 0 for every host bit. The 1s are always contiguous and always come first. Written like an address: 255.255.255.192.
  • Prefix length — the count of 1s in the mask, written after a slash. 255.255.255.192 has 8+8+8+2 = 26 ones, so it's /26.
  • Host bits — whatever's left over: 32 − prefix. A /26 has 6 host bits.
New to binary? Keep reading anyway The next few examples show addresses as 1s and 0s. You don't need to convert them yet. For now, just notice that a mask is a run of 1s followed by a run of 0s, and that the 1s mark the network part. The Binary section right after this one teaches the conversion, and these examples make more sense once you've done it.

The address 192.168.10.77/26 in binary, split at the prefix boundary:

ANDing: how a device finds its network address

A host or router gets the network address with a bitwise AND of the address and the mask. The rule: 1 AND 1 = 1, and anything else gives 0. Where the mask has a 1, the address bit passes through unchanged. Where the mask has a 0, the result is 0.

Address   11000000.10101000.00001010.01001101   192.168.10.77
Mask  AND 11111111.11111111.11111111.11000000   255.255.255.192
          ───────────────────────────────────
Network = 11000000.10101000.00001010.01000000   192.168.10.64
Why it's called a "mask": painter's tape

Before painting, you cover the parts of a wall you want to keep with masking tape. A subnet mask works the same way, just inverted. Where the mask has a 1, the tape has a gap and the address bit shows through. Where the mask has a 0, the tape covers the bit and it comes out 0. Peel the tape off and what's left is the network address, with the host part blanked out.

Where you've seen this before (Session 6) Before sending a packet, a host ANDs its own address with its mask and then ANDs the destination address with that same mask, its own. A host never knows the destination's mask. If the two results match, the destination is on the local network and the host ARPs for it directly. If they differ, the packet goes to the default gateway. Subnetting decides which of those two paths every packet takes.

In the neighborhood picture: if the letter is for your own street, you walk it over yourself. If it's for any other street, you drop it at the post office.

Every subnet has three kinds of address

AddressHost bits are…Can a host use it?In 192.168.10.64/26
Network addressall 0sNo. It identifies the subnet itself (e.g., in routing tables).192.168.10.64
Host addressesanything in betweenYes. These are the usable addresses..65 – .126
Broadcast addressall 1sNo. Packets sent here reach every host on the subnet.192.168.10.127

So a subnet with h host bits has 2h total addresses and 2h − 2 usable hosts. For a /26: 2⁶ = 64 total, 62 usable.

Why "− 2": the hotel floor

Picture a subnet as one floor of a hotel with 64 rooms, numbered 0 to 63. Room 0 isn't a room at all: it's the sign by the elevator that says which floor you're on (the network address). The last room holds the floor's PA system, which talks to every room at once (the broadcast address). Guests can only book the 62 rooms in between.

Every subnet loses exactly those two, no matter its size. A /30 with 4 addresses keeps 2 for hosts, and a /20 with 4,096 keeps 4,094.

Binary: the only math you need

You just saw that the mask, ANDing, and the network/host split all work one bit at a time. This section gives you the fluency to read those bits. An IPv4 address is 32 bits, written as four 8-bit octets in dotted decimal. To subnet, you only need to be comfortable with one octet at a time.

The eight place values

Bit position87654321
Power of 22⁷2⁶2⁵2⁴2³2²2¹2⁰
Place value1286432168421

All eight bits on is 128+64+32+16+8+4+2+1 = 255, which is why no octet can go above 255.

Decimal → binary: the subtraction method

Work left to right. If the place value fits in what's left, write 1 and subtract. If it doesn't fit, write 0. Example: 172

Read the bit column top to bottom: 172 = 10101100.

Binary → decimal: add up the 1s

11000000 has 1s in the 128 and 64 places, so 128 + 64 = 192. 01001101 has 1s in the 64, 8, 4, and 1 places, so 64 + 8 + 4 + 1 = 77.

Think of it like light switches

An octet is a row of 8 light switches, each labeled with its wattage: 128, 64, 32, 16, 8, 4, 2, 1. Flip some on, and the octet's value is the total wattage. To make 172, you flip on 128, 32, 8, and 4, because those add to 172. That's all binary conversion is: choosing which switches to turn on.

Each switch is worth double the one to its right, so there's exactly one way to make any number from 0 to 255.

The core technique

The method: block size, a.k.a. the magic number

You don't need to write out 32 bits for every problem. Only one octet is "interesting," and one subtraction tells you where every subnet in it starts.

Six steps, every time

  1. Get the mask. Turn the prefix into a dotted mask using the chart.
  2. Find the interesting octet. It's the first octet, reading left to right, where the mask is not 255. (It's usually neither 255 nor 0. On an octet boundary like /24, it's the octet right after the 255s.)
  3. Block size = 256 − mask value in that octet. This is the "magic number."
  4. Count by the block size from 0. The network value is the largest multiple that's ≤ the address's value in that octet. Octets to the left copy across, and octets to the right become 0.
  5. Broadcast = next network − 1. In the interesting octet: network + block − 1. Octets to the right become 255.
  6. First host = network + 1, last host = broadcast − 1 (applied to the last octet). Hosts = 2h − 2.
Block size is a ruler

Think of the interesting octet as a ruler from 0 to 255, with a tick mark every block-size units. For a /26, the marks are at 0, 64, 128, and 192. To place an address, find the mark at or just below its number: that's the network. The next mark, minus one, is the broadcast. For .77, the mark below is 64 and the next is 128, so the subnet runs .64 to .127.

It's the same thing you do when you ask which inch a 3¾-inch measurement falls in. Here the "inches" are just 64 units wide.

Designing subnets

Borrowing bits: carving one network into many

So far you've analyzed a subnet that already exists. Designing subnets works the other way: take a network, borrow host bits and turn them into subnet bits, and end up with more, smaller networks.

Original  /24  11111111.11111111.11111111.00000000   1 network, 254 hosts
Borrow 2  /26  11111111.11111111.11111111.11000000   4 subnets, 62 hosts each
                                          ↑↑ borrowed subnet bits

The two formulas

You want…FormulaWhere the bits come from
Number of subnets2ⁿn = bits borrowed = new prefix − original prefix
Usable hosts per subnet2ʰ − 2h = host bits left = 32 − new prefix
Subnets: 2ⁿ. Don't subtract 2. The −2 applies only to hosts, because it removes the network and broadcast addresses. Older textbooks also subtracted 2 from the subnet count and skipped the "subnet zero" and "all-ones subnet." Modern routers use both, and ITN teaches 2ⁿ. Borrowing 3 bits gives 8 subnets, not 6.

Every bit you borrow doubles the number of subnets and roughly halves the hosts in each one. That trade-off is the whole design decision.

The 7 holy steps of subnetting (the class method)

The same math as the formulas above, run as a checklist. Use it for "I need N subnets" problems.

  1. Determine the number of subnets you need.
  2. Write out your host bits. For a /24, that's the last octet: 00000000.
  3. Determine how many bits to borrow to get the number of subnets you need: the smallest n where 2ⁿ ≥ subnets needed. (2ⁿ = number of subnets, n = bits borrowed.)
  4. Turn on the borrowed bits (set them to 1, starting with the first host bit right after the existing network bits) and find the decimal value of the octet(s).
  5. Figure the new subnet mask by adding the decimal value from step 4 to the original (given) subnet mask. The original mask is the classful default only when you start from a /8, /16, or /24.
  6. Find the value of the lowest-order bit turned on in the new mask (the last borrowed bit). This is your subnet variable, the block size, and you count by it in the octet where that bit sits.
  7. Use the variable from step 6 to find the subnet ranges. Count up by it: each subnet starts one address after the previous subnet's broadcast.

Then, for any subnet: 2ʰ − 2 = usable hosts per subnet, where h is the number of host bits left.

7 steps · worked

192.168.10.0/24 needs 6 subnets

  1. Subnets needed: 6.
  2. Host bits (4th octet): 00000000.

  4. Turn on 3 bits: 11100000 = 128 + 64 + 32 = 224.
  5. Original mask 255.255.255.0 with 224 added to the last octet gives 255.255.255.224 (/27).
  6. The lowest-order bit turned on in 11100000 is the 32s place, so the variable is 32.
  7. Count by 32 to get 8 subnets. 5 host bits remain, so 2⁵ − 2 = 30 hosts each:

7 steps · across an octet

172.16.0.0/16 needs 75 subnets

  1. Subnets needed: 75.
  2. Host bits (3rd and 4th octets): 00000000.00000000.
  3. 2⁶ = 64 is too few, and 2⁷ = 128 is enough. Borrow 7 bits.
  4. Turn on 7 bits: 11111110.00000000. The 3rd octet becomes 128+64+32+16+8+4+2 = 254.
  5. Original mask 255.255.0.0 with 254 added to the 3rd octet gives 255.255.254.0 (/23).
  6. The lowest-order bit turned on is the 2s place in the 3rd octet, so the variable is 2, counted in the 3rd octet.
  7. Count by 2 in the 3rd octet: 172.16.0.0 – 172.16.1.255, then 172.16.2.0 – 172.16.3.255, and so on. The 75th subnet (#74) is 172.16.148.0/23. 9 host bits remain, so 2⁹ − 2 = 510 hosts each.
7 steps · not starting from a default mask

172.16.16.0/20 needs 4 subnets

  1. Subnets needed: 4.
  2. The original mask is /20 = 255.255.240.0. In the 3rd octet that's 11110000: the first 4 bits are already network, and the host bits start at the 5th bit.
  3. 2² = 4 is enough. Borrow 2 bits.
  4. Turn on the 2 bits right after the existing network bits: 00001100 = 8 + 4 = 12. (Not 128 + 64. The borrowed bits start where the host bits start, not at the left edge of the octet.)
  5. Original mask 255.255.240.0 with 12 added to the 3rd octet: 240 + 12 = 252, giving 255.255.252.0 (/22). Adding 12 to the classful default (255.255.0.0) would give 255.255.12.0, which isn't a valid mask. That's why step 5 says the original mask.
  6. The lowest-order bit turned on is the 4s place in the 3rd octet, so the variable is 4.
  7. Count by 4 in the 3rd octet, starting from 16: 172.16.16.0/22, 172.16.20.0/22, 172.16.24.0/22, 172.16.28.0/22. The last broadcast is 172.16.31.255, which is also the end of the original /20. 10 host bits remain, so 2¹⁰ − 2 = 1,022 hosts each.
Same answer, two routes Step 6's "lowest-order bit turned on" is exactly the block size from The Method. The last 1 in 11100000 is worth 32, and 256 − 224 = 32. Use whichever way of finding it sticks for you.
Borrowing bits is slicing a pizza

Each borrowed bit is one more cut through every slice. With no cuts you have 1 pizza. One cut gives 2 halves. Cut every piece again and you have 4 quarters, then 8, then 16. The number of slices doubles with each cut, and each slice is half the size it was.

That's also why you can't order exactly 6 subnets. Cutting only ever gives you 2, 4, 8, 16… so you round up to the next power of two (8) and keep the extras as spares.

Where it breaks: pizza slices don't lose anything, but every subnet gives up 2 addresses (network and broadcast). The more slices you cut, the more total addresses that costs.

The subnet ladder: 192.168.10.0/24, split further at each step

Each row borrows one more bit. Every block splits cleanly into two, and every subnet starts on a multiple of its own block size. VLSM depends on that alignment.

Design 3 · need H hosts per subnet

10.0.0.0/8, every subnet must hold 1,000 hosts

  1. Find the smallest h where 2ʰ − 2 ≥ 1,000: 2⁹ − 2 = 510 is too small, and 2¹⁰ − 2 = 1,022 works. Keep 10 host bits.
  2. New prefix: 32 − 10 = /22 (255.255.252.0). Block size 4 in the 3rd octet.
  3. Bits borrowed: 22 − 8 = 14, so 2¹⁴ = 16,384 subnets available.
  4. They run 10.0.0.0/22, 10.0.4.0/22, 10.0.8.0/22, … 10.0.252.0/22, then roll over to 10.1.0.0/22 (subnet #64), and so on up to 10.255.252.0/22.
Design 4 · both requirements

192.168.1.0/24 needs 5 subnets, each with at least 20 hosts

  1. Subnets: 2² = 4 is too few, and 2³ = 8 is enough. Borrow 3 bits, so the prefix must be /27 or longer.
  2. Hosts: 2⁴ − 2 = 14 is too few, and 2⁵ − 2 = 30 is enough. Keep at least 5 host bits, so the prefix must be /27 or shorter.
  3. Only one prefix satisfies both: /27 (255.255.255.224). That gives 8 subnets of 30 hosts: .0, .32, .64, .96, .128, .160, .192, .224.
  4. Sanity check: with 6 subnets of 40 hosts instead, subnets would need /27 or longer and hosts would need /26 or shorter. No prefix does both, so a single /24 can't meet that requirement with equal-size subnets.
Hosts first, or subnets first? When a problem gives both ("at least 8 subnets with 25 hosts each"), work out each requirement separately and check that they fit together. For a /24: 8 subnets needs /27, and 25 hosts needs /27 (30 hosts), so both are satisfied. The subnet count sets the shortest prefix you can use, and the host count sets the longest. Any prefix from one to the other works. If the subnet count needs a longer prefix than the host count allows, the block is too small.

Advanced design

VLSM: right-sizing every subnet

Variable Length Subnet Masking means using different prefix lengths inside one address block, so each subnet is sized to what it needs instead of making every subnet as big as the largest one.

Why fixed-size subnetting fails

You've been given 192.168.50.0/24 for a small office:

SegmentHosts neededSmallest fit
Sales LAN100/25 (126)
Engineering LAN50/26 (62)
HR LAN25/27 (30)
Guest Wi-Fi10/28 (14)
3 router-to-router WAN links2 each/30 (2)

With one mask for everything, the biggest need (100 hosts) forces /25 on every subnet. A /24 holds only two /25s, and you need seven subnets. It fails. VLSM uses the same /24 and fits all seven, with room to spare.

VLSM is loading a moving truck

Movers put the couch and fridge in first, then boxes, then shove the small stuff into the gaps. Load the shoeboxes first and the couch won't fit, even though the total volume would have. VLSM is the same: biggest subnets first, smallest last.

There's one extra rule trucks don't have: every subnet has to park on a line painted for its size. A /28 (16 addresses) can only start at .0, .16, .32, and so on, like a bus that can only use a bus bay. Going largest-first puts every subnet on a valid line automatically.

The three VLSM rules

  1. Sort largest to smallest. Allocate the biggest subnet first, from the start of the block.
  2. Start each subnet on a multiple of its own block size. Going largest-first makes this happen automatically.
  3. Allocate contiguously. Each subnet starts right after the previous broadcast. WAN /30s go last.

ITN describes the same idea as subnetting a subnet: split the block into equal subnets for the LANs, then take one unused subnet and split it again (for example, a /27 into eight /30s for WAN links). Largest-first gives the same kind of result, so expect to see both framings on the exam.

What goes wrong if you go smallest-first Put the three /30s at .0, .4, and .8, and the next free address is .12. Guest is a /28 (block 16), and 12 isn't a multiple of 16. So 192.168.50.12/28 isn't a real network address. AND it with .240 and you get .0, which means that "subnet" is really .0–.15, and it overlaps all three WAN links. To avoid the overlap you'd have to skip ahead to .16, which leaves a hole at .12–.15. In a tight plan those holes add up and break your free space into scraps. Going largest-first gives you alignment automatically and leaves all the spare space in one block at the end.
Checking a VLSM plan For each subnet, confirm three things. (1) The network address is a multiple of its block size. (2) It starts after the previous subnet's broadcast. (3) Usable hosts ≥ need. If all three hold for every row, the plan has no overlaps. The VLSM drill generates new scenarios for you to work.

Module 12

IPv6 subnetting: easier than it looks

An IPv6 address is 128 bits, which sounds much worse than IPv4. In practice you almost always subnet one 16-bit field, count in hex, and give every LAN a /64. There's no host math, no −2, and no broadcast address.

Reading an IPv6 address first

128 bits are written as eight hextets of 4 hex digits each, separated by colons. Two rules shorten them:

RuleWhat it doesExample
1 · Omit leading zerosDrop zeros at the front of any hextet. Never drop trailing zeros.0db8 → db8 · 000a → a · 0000 → 0
2 · Double colonReplace one run of consecutive all-zero hextets with ::. Use it only once per address, or the address becomes ambiguous.2001:db8:acad:0:0:0:0:1 → 2001:db8:acad::1
Full example 2001:0db8:acad:0001:0000:0000:0000:0010 → rule 1 → 2001:db8:acad:1:0:0:0:10 → rule 2 → 2001:db8:acad:1::10

Structure of a global unicast address (GUA)

2001:0db8:acad:0001:0000:0000:0000:0010
└─── 48 bits ──┘ └16┘ └────── 64 bits ──────┘

global routing prefix, assigned by your ISP / RIRsubnet ID, which you chooseinterface ID
  • Global routing prefix — commonly a /48, given to a site by its provider.
  • Subnet ID — the 4th hextet, 16 bits. 2¹⁶ = 65,536 subnets per /48.
  • Interface ID — the last 64 bits. Every LAN is a /64. That's 2⁶⁴ addresses per subnet, far more than you'll ever need.
A /48 is a whole office tower

Your ISP hands you an entire building (the /48). It has 65,536 floors, numbered 0000 to ffff (the subnet ID), and each floor has more rooms than you could ever fill (the 64-bit interface ID). Subnetting IPv6 is just choosing which floor each department gets. Nobody measures floors to see if a department fits, because every floor is enormous.

Hex trap After 9 comes a, not 10. :10: in a subnet ID is sixteen. Also note that the first subnet, number 0, compresses to 2001:db8:acad::/64. That's correct, not a typo.
Hex counting is an odometer with 16 digits

A car's odometer wheel shows 0–9 and then rolls over. A hex wheel shows 0–9, then a b c d e f, and only then rolls over to 10. So f is fifteen, 10 is sixteen, 1f is thirty-one, and 20 is thirty-two. Each hex digit is worth 16× the one to its right, just as each decimal digit is worth 10×.

    Troubleshooting your own work

    The ten classic traps

    Nearly every wrong subnetting answer comes from one of these. When you get something wrong, find which one it was.

    #TrapFix
    1Forgetting −2 on hosts. Saying a /26 holds 64 hosts.Total addresses = 2ʰ. Usable = 2ʰ − 2.
    2Subtracting 2 from subnets. Saying 3 borrowed bits give 6 subnets.Subnets = 2ⁿ. The −2 is for hosts only.
    3Wrong interesting octet. Applying a /20's block size of 16 to the 4th octet.The prefix row on the chart tells you the octet: /17–/23 → 3rd octet (/24 is an octet boundary).
    4Using the mask value as the block size. "Mask 240, so subnets go up by 240."Block = 256 − mask value = 16.
    5Octets to the right of the interesting octet. Writing 172.16.45.255 as the broadcast for 172.16.45.200/20.To the right: network gets 0s, broadcast gets 255s. Always.
    6Assigning the network or broadcast address to a host.Check that the address isn't all-0s or all-1s in the host bits.
    7Treating every .0 or .255 as special. In a /23, x.x.1.0 can be a valid host.Only all-0 or all-1 host bits matter, not the look of the last octet.
    8VLSM smallest-first. Subnets land off their block boundaries and overlap.Sort largest first. Every network address must be a multiple of its block size.
    9172.32.x.x is private. (It isn't.)The private range is 172.16 – 172.31 only.
    10Decimal counting in IPv6. Writing :10: for subnet ten, or using :: twice.Ten is :a:. Only one :: per address.
