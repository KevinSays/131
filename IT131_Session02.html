Overview

What Session 2 covers

Module 2 teaches you how to configure a switch from scratch. Module 3 explains why all those settings exist — the protocol suites and layered models that make devices from different manufacturers talk to each other.

  • Save and verify configurations with show commands

Module 2

Switch bootup process

Before you can configure anything, the switch has to boot. Understanding the boot sequence tells you where the config lives and what happens if something goes wrong.

Key memory types

running-config vs. startup-config
! running-config = what the switch is using RIGHT NOW (in RAM) ! startup-config = what the switch WILL use on next boot (in NVRAM) ! If you make changes but don't save, they vanish on reboot. Switch# show running-config ! current active config Switch# show startup-config ! saved config (what boots next time) Switch# copy running-config startup-config ! SAVE IT

Module 2

IOS CLI access & modes

Cisco IOS uses a hierarchical mode structure. You must be in the right mode to run a given command — this trips up every beginner.

Access methods

Three ways to reach the CLI
Console — physical cable, direct access Always works. No network needed. The "break glass" method. SSH — encrypted remote access over the network Requires: management IP + enable secret + line vty config. Preferred for day-to-day management. Telnet — unencrypted remote access Mentioned only to say "don't use it." Exists in the curriculum to contrast with SSH.

Module 2

Basic switch configuration

A complete initial switch configuration — hostname, security, management IP, SSH. This is the sequence you'll follow every time you touch a new switch.

Switch Initial Configuration (full walkthrough)
! === Step 1: Enter privileged EXEC mode === Switch> enable Switch# ! === Step 2: Enter global config mode === Switch# configure terminal Switch(config)# ! === Step 3: Set hostname === Switch(config)# hostname Floor1-SW Floor1-SW(config)# ! prompt changes immediately ! === Step 4: Secure privileged EXEC mode === Floor1-SW(config)# enable secret Cisco123 ! NEVER use "enable password" — it stores in plaintext ! === Step 5: Secure console port === Floor1-SW(config)# line console 0 Floor1-SW(config-line)# password ConP@ss Floor1-SW(config-line)# login Floor1-SW(config-line)# exit ! === Step 6: Secure remote access (SSH) === Floor1-SW(config)# line vty 0 4 Floor1-SW(config-line)# password VtYp@ss Floor1-SW(config-line)# login Floor1-SW(config-line)# transport input ssh Floor1-SW(config-line)# exit ! === Step 7: Set a legal warning banner === Floor1-SW(config)# banner motd # Enter TEXT message. End with the character '#' Authorized access only. All activity is monitored.# ! === Step 8: Configure management IP on VLAN 1 === Floor1-SW(config)# interface vlan 1 Floor1-SW(config-if)# ip address 192.168.1.10 255.255.255.0 Floor1-SW(config-if)# no shutdown ! VLAN 1 is up by default for data, but the SVI needs "no shutdown" ! === Step 9: Set default gateway (so switch is reachable from other subnets) === Floor1-SW(config)# ip default-gateway 192.168.1.1 ! === Step 10: SAVE the config === Floor1-SW(config)# end Floor1-SW# copy running-config startup-config ! Without this step, everything above is lost on reboot!
Verification commands
Floor1-SW# show running-config ! full current config Floor1-SW# show ip interface brief ! IP addresses on all interfaces Floor1-SW# show mac address-table ! MAC-to-port mapping Floor1-SW# show interfaces ! detailed interface status Floor1-SW# show version ! IOS version, uptime, config register Floor1-SW# show ip ssh ! SSH status and version

Module 3

OSI vs. TCP/IP models

Two models describe how networking works in layers. The OSI model is the reference vocabulary; the TCP/IP model is what the internet actually runs on.

Module 3

Encapsulation & decapsulation

As data moves down the protocol stack, each layer wraps it with its own header (and sometimes a trailer). This wrapping is encapsulation. At the receiving end, each layer strips its header — decapsulation.

IOS Modes

Which mode am I in?

You type configure terminal and the prompt changes to Switch(config)#. You then type interface fastethernet 0/1 and the prompt changes again. What mode are you in now, and what does the prompt tell you?

Show answer

Answer: You're in interface configuration mode — (config-if)#. The prompt encodes your position in the hierarchy: (config) means global config, (config-if) means you're inside a specific interface's config. You can only configure that interface's settings (speed, duplex, description) while in this mode.

Config save

The reboot surprise

You spend 20 minutes configuring a switch — hostname, passwords, management IP, SSH. You can ping the switch from a PC. The next morning, the switch reboots overnight and all your config is gone. What happened?

Show answer

Answer: You forgot to save. The changes you made were in running-config (RAM, volatile). When the switch rebooted, it loaded startup-config (NVRAM), which was never updated. The fix: always run copy running-config startup-config (or write memory) after finishing configuration.

SSH vs Telnet

Why SSH?

A student asks: "If both SSH and Telnet let me configure a switch remotely, why does it matter which one I use?"

Show answer

Answer: Telnet sends everything — including passwords — in plaintext. Anyone sniffing the network can read your credentials. SSH encrypts the entire session. On any production network, SSH is the only acceptable choice for remote management. Telnet exists in the curriculum so you understand why SSH replaced it.

OSI mapping

Which layer is it?

A switch forwards traffic using MAC addresses. A router forwards traffic using IP addresses. A firewall inspects traffic based on security rules. At which OSI layer does each device primarily operate?

Show answer

Switch → Layer 2 (Data Link) — it uses MAC addresses to make forwarding decisions.

Router → Layer 3 (Network) — it uses IP addresses to route packets between networks.

Firewall → Layers 3–7 — it can filter based on IP addresses (L3), port numbers (L4), or application content (L7), depending on its capabilities.

Encapsulation

What's the PDU?

A web browser sends an HTTP request to a server on another network. Starting from the application layer, what is the PDU called at each layer as the data moves down the stack?

Show answer

Layer 7 (Application): Data — the HTTP request itself.

Layer 4 (Transport): Segment — TCP wraps the data with source and destination port numbers (e.g., port 443 for HTTPS).

Layer 3 (Network): Packet — IP wraps the segment with source and destination IP addresses.

Layer 2 (Data Link): Frame — Ethernet wraps the packet with source and destination MAC addresses plus an error-check trailer (FCS).

Layer 1 (Physical): Bits — the frame is converted to electrical/optical signals on the wire.

Management IP

Why VLAN 1?

Why do we configure the switch's management IP on interface vlan 1 instead of on a physical port like fastethernet 0/1?

Show answer

Answer: A physical port (like Fa0/1) is a Layer 2 port — it forwards frames, not packets. It doesn't have (or need) an IP address. The management IP needs to sit on a Layer 3 interface so the switch can be reached via IP for remote management. interface vlan 1 is a Switch Virtual Interface (SVI) — a virtual Layer 3 interface associated with VLAN 1. By default, all access ports are in VLAN 1, so any port on the switch can reach this management IP.
